## 1. 임베딩 모델

텍스트를 의미 기반 벡터로 변환하는 모델입니다.

| 임베딩 모델 | 용도 |
| --- | --- |
| BGE-M3 | Dense·Sparse 벡터 생성 가능 |
| KURE-v1 | 한국어 중심 Dense 벡터 생성 |
| Qwen3-Embedding-0.6B | 다국어 Dense 벡터 생성 |

BM25와 Nori는 임베딩 모델이 아닙니다.

## 2. 검색 방식

저장된 데이터에서 관련 청크를 찾는 방법입니다.

| 검색 방식 | 설명 |
| --- | --- |
| BM25 | 질문과 청크의 동일 단어를 기반으로 검색 |
| BM25-Nori | Nori 형태소 분석을 적용한 한국어 BM25 |
| Dense Search | 임베딩 벡터의 의미적 유사도로 검색 |
| Sparse Search | 중요한 단어를 희소 벡터로 표현해 검색 |
| Hybrid Search | BM25 또는 Sparse와 Dense 검색 결과를 결합 |
| Reranking | 1차 검색 결과를 별도 모델로 다시 정렬 |

여기서 **BM25-Nori는 별도의 검색 원리가 아니라 BM25에 한국어 분석기를 적용한 설정**입니다.

## 전체 결과

`Complete@5`는 일단 제외하고 7개 지표 평균을 다시 계산했습니다.

| 검색 방식 | 7개 지표 평균 | Hit@3 | Recall@5 | nDCG@5 |
| --- | --- | --- | --- | --- |
| BM25-Nori | 39.02% | 52.50% | 52.22% | 43.44% |
| BGE-M3 Sparse | 39.97% | 55.83% | 54.86% | 44.44% |
| 일반 Hybrid | 48.93% | 65.00% | 67.19% | 55.37% |
| 일반 Dense | 49.31% | 66.67% | 67.78% | 56.01% |
| Structured Dense | 54.17% | 71.67% | **73.06%** | 62.66% |
| Structured Hybrid | 54.52% | 72.50% | 72.64% | 62.99% |
| Hybrid + Reranker | **59.15%** | **80.83%** | **80.42%** | **68.00%** |

### 의외의 결과 1: 일반 Hybrid가 Dense보다 낮음

기존 예상은 다음이었습니다.

```
Dense + BM25
→ 의미 검색과 키워드 검색이 서로 보완
→ Dense 단독보다 성능 향상
```

그런데 결과는 반대였습니다.

- Dense Hit@3: 66.67%
- Hybrid Hit@3: 65.00%
- Dense Recall@5: 67.78%
- Hybrid Recall@5: 67.19%

차이는 작고 통계적으로 확정적인 수준은 아니지만, 최소한 **BM25 15%를 넣는 것만으로 자동 개선되지는 않았다**고 볼 수 있습니다.

원인은 다음 가능성이 큽니다.

- BM25가 문서에 반복되는 공통 키워드에 높은 순위를 부여
- `신청`, `지급`, `대상`, `서류` 같은 표현이 여러 업무에 반복
- 업무 필터가 없으므로 BM25 후보가 다른 업무까지 끌어옴
- RRF가 Dense의 올바른 순위를 일부 밀어냄
- Dense 0.85, BM25 0.15라는 가중치가 현재 데이터에 최적화된 값은 아님

따라서 `Hybrid이므로 Dense보다 좋을 것`이라는 가정은 성립하지 않았습니다.

## 의외의 결과 2: Structured Hybrid도 Structured Dense와 거의 동일

Structured Hybrid가 Structured Dense보다 약간 높기는 합니다.

- Hit@3: +0.83%p
- MRR@10: +0.90%p
- MAP@10: +0.84%p
- nDCG@5: +0.33%p
- Recall@5: 오히려 -0.42%p

질문별로 비교하면:

- Hit@3 개선: 2개
- Hit@3 악화: 1개
- 나머지 117개: 동일

부트스트랩 신뢰구간도 모든 주요 지표에서 0을 포함했습니다. 즉, 현재 결과만 보면 **Structured Dense에 BM25를 추가한 효과는 거의 없다고 보는 것이 맞습니다.**

이것은 Structured Dense 자체가 이미 제목·부제목·경로의 키워드 정보를 포함하기 때문일 수 있습니다.

```
Structured Dense
= 의미 정보
+ 제목 키워드
+ 부제목 키워드
+ 브레드크럼
+ 본문
```

BM25가 추가로 제공해야 할 키워드 정보가 Structured 입력과 상당 부분 중복된 것입니다.

## 의외의 결과 3: Parent–Child의 효과가 크지 않음

Parent–Child 확장 결과는 다음과 같습니다.

- 확장 전 Child Gold Recall: 72.64%
- 확장 후 Gold Recall: 74.03%
- 평균 개선: **+1.39%p**
- 개선된 질문: 6개
- 악화된 질문: 3개
- 변화 없음: 111개

개선 사례는 Parent–Child가 원래 기대한 대로 작동했습니다.

- EVAL024: 예금보험금 신청 절차
- EVAL027: 가지급금과 개산지급금 차이
- EVAL073: 착오송금 대리인 추가 서류
- EVAL080: 착오송금 방문 접수센터 운영시간
- EVAL084: 잘못 보낸 돈 반환 가능 여부
- EVAL126: 횡령·배임 신고 구분

그런데 평균 컨텍스트는 다음처럼 증가했습니다.

- 확장 컨텍스트: 평균 6.4개 청크
- 추가된 청크: 평균 2.03개
- 평균 컨텍스트 길이: 약 1,896자
- Gold에 표시되지 않은 청크 비율: 83.18%

`Gold 미표기=무관`은 아니지만, **컨텍스트와 토큰은 늘었는데 정답 근거 포함률은 1.39%p만 증가**했습니다. 모든 질문에 일괄 적용하기에는 효율이 좋지 않습니다.

### Parent–Child 평가기에서 수정할 부분

Recall이 악화된 3개 질문은 Parent를 최대 3개로 제한하면서, 상위 Child 5개 중 네 번째·다섯 번째 Parent의 seed 청크가 컨텍스트에서 빠졌기 때문입니다.

즉 다음처럼 바꿔야 합니다.

```
현재
Parent 최대 3개
→ 나머지 Parent의 seed Child도 제거될 수 있음

수정
상위 seed Child 5개는 무조건 보존
→ 상위 Parent 3개에 대해서만 인접 청크 추가
```

Parent–Child 확장은 기존 검색 결과를 보강해야 하므로, **확장 후 Recall이 확장 전보다 낮아지면 안 됩니다.**

## Reranker 효과는 실제로 큼

Reranker는 Structured Hybrid보다 다음만큼 개선됐습니다.

- Hit@3: +8.33%p
- Recall@5: +7.78%p
- MRR@10: +2.49%p
- MAP@10: +3.13%p
- nDCG@5: +5.01%p
- F1@5: +3.31%p

통계적으로도 Hit@3, Recall@5, F1@5 개선은 비교적 확실하게 나타났습니다.

다만 모든 질문이 개선된 것은 아닙니다.

- Hit@3 개선: 14개
- Hit@3 악화: 4개
- 동일: 102개

악화된 대표 질문:

- EVAL011: 투자신탁 상품도 보호 대상인가요?
- EVAL035: 돌아가신 가족의 예금보험금 신청
- EVAL063: 착오송금 반환지원 신청 위치
- EVAL100: 부채증명원 발급 방법

따라서 Reranker를 모든 질문에 적용하기보다는 이전에 논의한 것처럼 선택적으로 적용하는 방향이 여전히 타당합니다.

```
단순 질문
→ Structured Dense

복합 조건·필요 서류·신청 절차
→ Structured Dense 또는 Hybrid
→ Reranker 적용

검색 신뢰도가 낮거나 업무 청크가 혼입됨
→ Reranker 적용
```

## Complete@5 결과는 현재 잘못 계산됨

대시보드에는 모든 방식의 `complete_applicable_count`가 120으로 표시되어 있습니다. 하지만 실제 적용 대상은 18개뿐입니다.

`Complete@5`는 다음 조건에만 적용돼야 합니다.

```
multi_chunk_required = Y
주요 Gold 청크가 2개 이상
주요 Gold 청크가 5개 이하
```

원본 기준으로 재계산한 결과입니다.

| 검색 방식 | 올바른 Complete@5 | 성공 |
| --- | --- | --- |
| BM25-Nori | 5.56% | 1/18 |
| Dense | 11.11% | 2/18 |
| 일반 Hybrid | 11.11% | 2/18 |
| Sparse | 16.67% | 3/18 |
| Structured Dense | **22.22%** | 4/18 |
| Structured Hybrid + Parent–Child | 16.67% | 3/18 |
| Hybrid + Reranker | **22.22%** | 4/18 |

대시보드가 적용 대상이 아닌 빈값을 `0`으로 변환하면서 120개 전체 평균을 낸 것으로 보입니다. 따라서 현재 표시된 8개 지표 단순 평균도 그대로 사용하면 안 됩니다.

## 도메인별로 보면

### 예금자보호제도

Structured Dense가 매우 강합니다.

- Structured Dense Hit@3: 77.78%
- Reranker Hit@3: 72.22%
- Reranker Recall@5: 80.56%

첫 정답 적중은 Structured가 좋고, 여러 근거 회수는 Reranker가 좋습니다.

### 예금보험금 안내

전체적으로 어려운 도메인입니다.

- Structured Dense Recall@5: 67.59%
- Reranker Recall@5: 71.30%
- Structured Hybrid Recall@5: 59.26%

BM25 결합이 오히려 Recall을 크게 낮췄습니다. 이 도메인은 Structured Dense 또는 Reranker가 적합합니다.

### 고객 미수령금

Reranker 효과가 큽니다.

- Structured Dense Hit@3: 50.00%
- Structured Hybrid Hit@3: 50.00%
- Reranker Hit@3: **81.25%**

다른 도메인의 근거를 함께 사용하는 질문이 있어 단순 업무 필터보다 Reranker가 효과적으로 보입니다.

### 착오송금

Structured Hybrid가 Structured Dense보다 조금 좋고, Reranker가 가장 좋습니다.

- Structured Dense Hit@3: 66.67%
- Structured Hybrid Hit@3: 70.37%
- Reranker Hit@3: 74.07%

조건·절차·서류 표현이 많아 키워드 보완과 재정렬 효과가 있습니다.

### 채무조정

Structured Dense가 기본 검색기로 충분히 강합니다.

- Structured Dense Hit@3: 81.25%
- Reranker Hit@3: 87.50%

비용을 고려하면 Structured Dense를 기본으로 두고 복잡한 질문에만 Reranker를 쓰는 것이 적절합니다.

### 은닉재산 신고

Reranker가 압도적입니다.

- Reranker Hit@3: 100%
- Recall@5: 90.67%
- MRR@10: 90.67%

다만 BM25도 MRR@10이 77.90%로 의외로 높습니다. 은닉재산 도메인은 공식 용어가 질문과 문서에 그대로 반복되기 때문에 키워드 검색이 잘 작동한 것으로 보입니다.

## 모든 방식이 공통으로 실패한 질문

Hit@3 기준으로 15개가 모든 검색 방식에서 실패했습니다.

대표 유형은 다음과 같습니다.

- 보호대상 금융회사·상품 구분
- 예금보험금 필요 서류·대리 신청
- 미수령금 조회
- 착오송금 동의 거부·법적 근거·운영시간
- 개인회생 분할상환 기간

이 질문들은 검색기만 교체해서 해결되지 않을 가능성이 큽니다.

확인해야 할 것은 다음입니다.

1. Gold 청크가 정말 질문의 직접 답변인가?
2. Gold보다 더 직접적인 다른 청크가 존재하지 않는가?
3. 해당 청크 본문에 질문 표현이 실제로 포함되어 있는가?
4. 청크 크기가 너무 크거나 작은가?
5. 제목·부제목이 본문과 맞는가?

## 120개 결과라는 점도 주의해야 함

최신 파일에는 126개 질문이 있지만 `evaluation_target=N`인 6개가 제외돼 이번 결과는 120개 기준입니다.

제외된 질문:

- EVAL010: 어떤 금융상품이 보호되나요?
- EVAL012: 보호상품과 비보호상품 구분
- EVAL025: 예금보험금 지급 소요기간
- EVAL042: 재외국민 미수령금 신청
- EVAL043: 법인 미수령금 신청
- EVAL050: 가족 대리 미수령금 신청

이 6개까지 평가할 의도였다면 `evaluation_target` 정책부터 다시 확정해야 합니다.

## 현재 추천안

| 용도 | 추천 방식 |
| --- | --- |
| 기본 검색기 | **BGE-M3 Structured Dense** |
| 복합·신청·서류 질문 | Structured Dense + Reranker |
| 착오송금 | Structured Hybrid 후보 유지 |
| 은닉재산 단순 질문 | BM25-Nori 또는 Structured Dense |

| 모호한 질문 | 검색보다 추가 질문 우선 |

결론적으로 이번 결과는 다음처럼 해석하는 것이 적절합니다.

> Structured 입력은 효과가 분명했지만, BM25를 단순 결합하는 것과 Parent–Child를 일괄 적용하는 것은 비용 대비 개선 폭이 작았다. Reranker는 정답 회수율을 유의미하게 높였으므로, Structured Dense를 기본 검색기로 사용하고 복잡하거나 검색 신뢰도가 낮은 질문에 선택적으로 적용하는 구조가 가장 현실적이다.
> 

다음 재실험 전에는 먼저 `Complete@5` 계산과 Parent–Child seed 보존 로직을 수정해야 합니다.
