# 결정 과정과 평가 해석

## 검색: 모델과 검색 방식을 구분

BGE-M3를 중심으로 Dense·Sparse를 비교하고, BM25/Nori와 Hybrid, Reranker, Structured 입력, Parent–Child를 실험했습니다. 모델명만 같아도 입력 텍스트 구성, 후보 깊이, 필터, 결합 방식, 평가 K가 다르면 결과는 달라집니다.

## 질의 이해: V1.5 선정

V3.1, V2.2, V1.5 후보를 비교하며 안전한 검색 이관, LLM 호출량, 지연시간을 함께 고려했습니다. 최종 선정 명칭은 V1.5입니다. 초기 자료에는 교차 업무만 분해하거나 원문 가중치를 섞은 실험이 있고, 후반에는 복합질의를 분해해 적용하는 방향으로 정리되었습니다. 원본 노트와 최신 런타임의 분기 조건이 완전히 같은 버전이라고 단정하지 않습니다.

## 답변: C 기본, 교차 업무 비교는 D

C는 Evidence Pack에 사전 Fact Index를 보강하는 방식입니다. D는 LLM으로 Answer Skeleton을 생성한 후 답변을 작성하는 방식입니다. 모든 복합질문에 무조건 D를 적용한다는 의미는 아닙니다. 실제 동작 조건은 함께 보관한 런타임 코드와 버전별 설계 노트를 확인합니다.

## 운영: 편집과 적용을 분리

설정·청크·프롬프트·질의 캐시 변경을 초안으로 준비하고 비교·승인·롤백과 연결하는 방향으로 관리 기능을 확장했습니다. 자료 업로드 브랜치를 바로 배포 브랜치로 사용하지 않습니다.

## 과거 지표 해석 주의

- 각 지표의 K, 분모, 제외 질문, Gold 정의를 확인합니다.
- 서로 다른 K에서 Recall 증가·Precision 감소는 더 많은 후보를 보는 효과를 함께 포함합니다.
- 지표 단순평균의 상승·하락은 통계적으로 검증된 종합 품질 판정이 아닙니다.
- Complete@K는 해당 버전의 대상 조건과 계산식을 확인해야 하며 최종 발표 선정 근거에서 제외된 자료가 있습니다.
- 실행 순서·캐시·워밍업에 영향을 받는 평균 지연시간을 동일 조건의 벤치마크로 단정하지 않습니다.
- 여러 과거 평가표를 한 표로 합산하지 않습니다. `reports/`의 각 실행은 별도 실험 기록입니다.
