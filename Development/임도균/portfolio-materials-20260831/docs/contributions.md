# 담당 역할과 개발 과정

## 출발점: 결과를 비교하기 어려웠다

검색 방식별 결과를 엑셀로만 읽으면 어떤 방식이 어떤 질문에서 잘 작동하는지 파악하기 어려웠습니다. Colab 평가기를 만들고, 파일을 올리면 지표와 질문별 결과를 볼 수 있는 HTML 대시보드로 연결했습니다.

대시보드는 이름 수정, 검색 방식 보관·복원, 색상 설정, 다중 청크 질문 필터, Gold 검수 경고, AI 분석용 내보내기 등 반복 실험 과정의 요구에 맞춰 개선했습니다.

## 설정 입력이 흩어져 실험 조건이 불명확해졌다

파이프라인·검색 평가·챗봇 테스트에 파라미터 입력이 각각 존재했습니다. 변경값 유실과 화면별 설정 혼동이 발생해, 수정한 설정에 이름을 붙여 저장하고 다시 불러오는 방식으로 정리했습니다.

- 파이프라인과 빠른 수정 패널: 설정 편집
- 파라미터 설정 관리: 이름을 붙인 설정 보관
- 검색 평가·챗봇 테스트: 저장된 설정 선택과 조건 확인
- 반영센터: 운영 적용 승인 및 이력 관리

편집·검증·운영 반영의 역할을 나눈 것이 핵심입니다. 개선 효과를 수치로 측정하지 않은 부분에 대해 생산성 향상률을 주장하지 않습니다.

## 관리자 화면을 실제 챗봇과 연결했다

HTML/CSS/Vanilla JS 관리자 UI를 서버 API와 연결했습니다. 파이프라인 조회, 허용된 파라미터 설정, 프롬프트 관리, 청크 변경, 검색 평가, 답변 비교, 반영·복구를 구성했습니다. 운영 중 소스 코드를 직접 수정하는 방식 대신 허용된 설정을 관리하는 방향을 선택했습니다.

## 관찰 가능한 운영을 지향했다

캐시 응답이 최초 생성의 토큰·시간을 재사용해 표시하던 문제를 확인했습니다. 이번 요청과 최초 생성 비용을 구분하고 캐시 적중, 실제 사용 토큰, 요청 응답시간을 로그에서 확인하도록 발전시켰습니다. 기간 집계와 페이지에 표시되는 로그 개수도 구분했습니다.

## 작업 경계

팀원들이 만든 질의분석·검색·답변 생성·수집 파이프라인과 공동으로 연동한 결과입니다. 이 저장소의 관리자 기능과 실험 도구가 개인 담당 영역이며, 전체 챗봇을 혼자 만들었다는 의미는 아닙니다. 파일별 원본 출처는 inventory를 참고하세요.
