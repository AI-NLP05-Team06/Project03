# KDIC 검색 품질 평가 — v3.5 업무 필터 미적용 버전

`Evaluation_DataSet_v3.5.xlsx`를 기준으로 예금보험공사 RAG 검색기의 성능을 비교하기 위한 Colab 평가 패키지입니다.

기존 검색기는 평가 질문의 정답 업무인 `gold_business_function`을 검색 필터로 적용했지만, 이번 버전에서는 업무 필터를 제거하고 전체 427개 청크를 대상으로 검색합니다.

BM25부터 Dense, Sparse, Hybrid, Reranker까지 총 6개 방식을 동일한 평가 데이터셋과 지표로 비교할 수 있도록 구성했습니다.

## 2. 평가 흐름

```text
Evaluation_DataSet_v3.5.xlsx
        ↓
평가 질문 및 Gold 청크 로드
        ↓
KDIC_output.zip에서 427개 청크 로드
        ↓
Gold 청크 무결성 검사
        ↓
업무 필터 없이 전체 청크 검색
        ↓
질문별 Top-10 검색 결과 생성
        ↓
Gold 청크와 검색 결과 비교
        ↓
검색 품질 지표 계산
        ↓
결과 CSV·JSON·ZIP 생성
        ↓
검색평가 비교 대시보드에 등록
```

이번 평가에서는 질문의 정답 업무를 검색기에 미리 제공하지 않습니다.

```text
기존 방식
질문 → Gold 업무 확인 → 해당 업무 청크만 검색

이번 방식
질문 → 전체 427개 청크 검색
```

따라서 다른 업무의 유사한 청크가 검색 결과에 섞이는지 확인할 수 있습니다.

원본 파일과 패키지에 포함된 사본의 SHA-256 해시도 동일하게 확인했습니다.


청크 ID 자체는 변경하지 않습니다.

## 4. 검색 방식

### 4.1 BM25 Nori Discard

한국어 형태소 분석기인 Nori를 적용한 키워드 검색입니다.

```text
사용자 질문
    ↓
Nori 형태소 분석
    ↓
복합어 분해 결과 중 원형 제거(Discard)
    ↓
BM25 점수 계산
    ↓
Top-10 청크 반환
```

주요 설정:

```text
Nori Decompound Mode: discard
BM25 k1: 1.5
BM25 b: 0.75
Top-K: 10
업무 필터: 미적용
```

HCX API 키와 GPU가 필요하지 않습니다.

### 4.2 BGE-M3 Dense Content

질문과 청크 본문을 1024차원 벡터로 변환하고 코사인 유사도로 검색합니다.

```text
질문 → BGE-M3 질문 벡터
청크 본문 → 기존 BGE-M3 청크 벡터
                ↓
          코사인 유사도
                ↓
           Top-10 반환
```

문서 표현:

```text
content
```

주요 설정:

```text
Embedding Model: bge-m3
Embedding Dimension: 1024
Similarity: Cosine Similarity
Top-K: 10
업무 필터: 미적용
```

질문 임베딩 생성을 위해 `HCX_API_KEY`가 필요합니다.

### 4.3 BGE-M3 Dense Structured

청크 본문뿐 아니라 제목, 소제목, 브레드크럼을 함께 임베딩하는 방식입니다.

```text
제목
+ 소제목
+ 브레드크럼
+ 본문
    ↓
BGE-M3 구조화 문서 벡터
    ↓
질문 벡터와 코사인 유사도 계산
    ↓
Top-10 반환
```

문서 표현 예시:

```text
제목: 보호한도
소제목: 예금자보호 한도
경로: 예금자보호제도 > 보호한도
본문: 원금과 소정이자를 합하여 1인당...
```

주요 설정:

```text
Embedding Model: bge-m3
Document Fields:
- title
- section_title
- heading_path
- content

Similarity: Cosine Similarity
Top-K: 10
업무 필터: 미적용
```

최초 실행 시 427개 구조화 문서를 임베딩합니다. 생성된 벡터는 결과 폴더에 캐시되어 같은 설정으로 재실행할 때 재사용할 수 있습니다.

`HCX_API_KEY`가 필요합니다.

### 4.4 BGE-M3 Sparse

BGE-M3에서 생성한 `lexical_weights`를 이용하는 Sparse 검색입니다.

```text
질문 → 토큰별 가중치
청크 → 토큰별 가중치
          ↓
   Sparse 점수 계산
          ↓
     Top-10 반환
```

주요 설정:

```text
Model: BAAI/bge-m3
Passage Max Length: 2048
Query Max Length: 512
Top-K: 10
업무 필터: 미적용
```

HCX API 키는 필요하지 않지만 BGE-M3 모델을 로컬로 실행하므로 Colab T4 GPU 사용을 권장합니다.

### 4.5 Hybrid A

BGE-M3 Dense 검색 결과와 BM25 Nori 검색 결과를 Weighted RRF로 결합합니다.

```text
BGE-M3 Dense Top-10 ─┐
                      ├→ Weighted RRF → 최종 Top-10
BM25 Nori Top-10 ────┘
```

주요 설정:

```text
Dense Weight: 0.85
BM25 Nori Weight: 0.15
RRF Constant: 10
각 검색기 후보 수: 10
최종 Top-K: 10
업무 필터: 미적용
```

Weighted RRF 계산식:

```text
RRF Score
= 0.85 / (10 + Dense Rank)
+ 0.15 / (10 + BM25 Rank)
```

질문 Dense 임베딩 생성을 위해 `HCX_API_KEY`가 필요합니다.

### 4.6 Hybrid A + Reranker

Hybrid A로 후보를 검색한 뒤 BGE Reranker가 질문과 청크의 관련성을 다시 계산합니다.

```text
BGE-M3 Dense Top-10 ─┐
                      ├→ Weighted RRF
BM25 Nori Top-10 ────┘
            ↓
      최대 20개 후보
            ↓
BAAI/bge-reranker-v2-m3
            ↓
      최종 Top-10
```

주요 설정:

```text
Dense Weight: 0.85
BM25 Nori Weight: 0.15
RRF Constant: 10
검색기별 후보: 10
Reranker 후보: 최대 20
최종 Top-K: 10
Reranker Model: BAAI/bge-reranker-v2-m3
Reranker Max Length: 512
업무 필터: 미적용
```

Reranker 입력에는 다음 필드를 사용합니다.

```text
title
section_title
heading_path
content
```

질문 Dense 임베딩에는 `HCX_API_KEY`가 필요하고, Reranker는 Colab GPU에서 실행합니다.

## 5. 평가 지표

모든 검색 방식은 동일한 지표로 평가합니다.

```text
Hit@3
Recall@5
MRR@10
MAP@10
Complete@5
nDCG@5
Precision@5
F1@5
검색 지연시간
```

### 지표 설명

| 지표 | 의미 |
|---|---|
| Hit@3 | 상위 3개 중 Gold 청크가 하나라도 포함되었는지 |
| Recall@5 | 필요한 Gold 청크 중 상위 5개에서 찾은 비율 |
| MRR@10 | 첫 번째 Gold 청크가 얼마나 높은 순위에 등장했는지 |
| MAP@10 | 여러 Gold 청크의 순위와 검색 정확도를 함께 평가 |
| Complete@5 | 필요한 근거 청크가 상위 5개에 모두 포함되었는지 |
| nDCG@5 | 중요도가 높은 Gold 청크가 상위에 배치되었는지 |
| Precision@5 | 상위 5개 중 Gold 청크가 차지하는 비율 |
| F1@5 | Precision@5와 Recall@5의 조화평균 |
| 검색 지연시간 | 질문 1건의 검색에 소요된 시간 |

`Complete@5`는 모든 질문에 적용하지 않고, 복수의 근거 청크가 필요한 질문에만 적용합니다.

## 7. HCX API 키 설정

HCX API를 사용하는 검색 방식은 Colab Secrets에서 API 키를 읽습니다.

사용하는 Secret 이름:

```text
HCX_API_KEY
```

Colab 왼쪽 메뉴에서 다음 순서로 등록합니다.

```text
보안 비밀 → 새 보안 비밀 추가
이름: HCX_API_KEY
값: 실제 API 키
노트북 액세스 허용: 활성화
```

API 키가 필요한 방식:

```text
BGE-M3 Dense Content
BGE-M3 Dense Structured
Hybrid A
Hybrid A + Reranker
```

API 키가 필요하지 않은 방식:

```text
BM25 Nori Discard
BGE-M3 Sparse
```

## 8. 결과 파일

각 평가 결과 ZIP에는 다음 파일이 포함됩니다.

```text
summary.json
run_config.json
question_results.csv
summary_by_domain.csv
missing_gold.csv
```

Hybrid Reranker 결과에는 적용 전후 비교 파일도 포함됩니다.

```text
comparison_before_after.csv
```

주요 파일 역할:

| 파일 | 내용 |
|---|---|
| `summary.json` | 전체 평균 평가 결과와 실행 설정 |
| `run_config.json` | 모델명, Top-K, 필터 여부 등 실행 조건 |
| `question_results.csv` | 질문별 검색 순위와 평가 점수 |
| `summary_by_domain.csv` | 업무 도메인별 평균 결과 |
| `missing_gold.csv` | 실제 청크에 존재하지 않는 Gold ID |
| `comparison_before_after.csv` | Reranker 적용 전후 지표 차이 |

## 10. 비교 시 주의사항

업무 필터 적용 효과를 확인하려면 다음 조건을 동일하게 유지해야 합니다.

```text
동일한 Evaluation_DataSet_v3.5.xlsx
동일한 KDIC_output.zip
동일한 Top-K
동일한 Dense·BM25 가중치
동일한 RRF 상수
동일한 Reranker 모델
```

두 실험의 차이는 다음 값만 달라야 합니다.

```text
업무 필터 적용 버전: domain_filter = true
업무 필터 제거 버전: domain_filter = false
```

데이터셋이나 검색 파라미터까지 함께 변경하면 성능 차이가 업무 필터 때문인지 다른 조건 때문인지 판단하기 어렵습니다.
